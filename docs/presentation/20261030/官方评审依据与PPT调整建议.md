# 官方评审依据与PPT调整建议

检索日期：2026-10-30。研究对象为2026“数字马力杯”第十三届浙江省大学生服务外包创新应用大赛，本科生组、A14和利时命题；未用全国服创赛同编号题目或其他年份标准替代。

## 一、已核验的官方依据

1. 浙江工业大学发布的本届通知：<https://www.soft.zjut.edu.cn/4073.html>。
2. 通知附件2《2026参赛指南》：已从通知中的真实附件链接下载并用macOS textutil提取全文。本地原件见“官方评审资料/2026参赛指南.doc”，文本见同目录txt。
3. 通知附件1《2026统一命题》ZIP：已下载并提取其中A14原始docx和文本，见“官方评审资料/A14官方命题.docx”和txt。

## 二、决赛与网评分开看

《参赛指南》三（四）表二：

| 决赛指标 | 权重 | 官方说明 |
|---|---:|---|
| 项目完成情况 | 50% | 考核参赛团队项目完成质量 |
| 介绍展示 | 20% | 考核参赛团队现场介绍水平 |
| 回答问题 | 30% | 考核参赛团队现场回答问题情况 |

表一网评为项目创意20%、实施方案30%、技术实现与交付30%、项目展示与团队协作20%。A14末尾提及的初赛统一标准，不能当作决赛权重。

本科作品另强调设计创新性、技术先进性、完整性，并考虑功能正确性、工作量和实现难度；所有作品考察开发过程是否符合相关产业研发业务流程。

指南对核心内容PPT表述为“10分钟以内为宜”，不能据此断言正式决赛现场的陈述/问答分段时长；本方案仍采用用户明确的10分钟汇报时长。

## 三、指南中容易漏掉的要求

- 团队角色须包含项目负责人、技术负责人、客户关系经理，对应成员需承担相应职责，并在方案及演示答辩中体现。
- 过程与结果并重、任务与团队并重，考虑成果与团队具体贡献的关联。
- 业务分析、技术、可行性、商业成本、管理均在考察范围内。
- 解决方案要求含目标与服务模型、组织管理与业务分析、技术路线、成本模型及可行性分析。
- 提交文字、视频等需匿名，避免学校和指导教师信息及暗示；后续PPT默认沿用匿名规范，现场若有新明确规定再适配。

## 四、A14命题的明确交付逻辑

自然语言需求→Agent结构化调度→算法库执行→模型评价反馈调整前置参数→图文报告和优选数据导出。

包含管理/清洗、动态优选、时滞/共线性、辨识评价、反馈寻优、自然语言工作流、报告与导出。任务还要求仿真测试集生成工具。提交物包含产品使用手册、交互演示、详细分工及过程文档。

## 五、把官方条款翻译成评委可能追问的问题（以下是推断）

| 评委可能关心的问题 | PPT提供的证据 |
|---|---|
| 对企业工作流的理解准确吗？ | 建模工程师的一次任务，以及需要返工的环节 |
| 功能是否真正完成并连通？ | 同一份CSV从上传至下载交付物的真实流程 |
| 比人工/普通流水线多解决了什么？ | 互补信息选段、模型评价反馈、Agent真实调用及数值溯源 |
| 结果能复核吗？ | 基线、测试协议、真实曲线、适用范围；不只报单个分数 |
| 企业开始使用需要哪些条件？ | 数据接口、部署条件、模型调用成本、计算预算、人工复核节点 |
| 团队是否理解并完成了这些工作？ | 角色、具体负责内容、迭代问题与验收成果 |

这些不是已公布的具体评委问答清单，也没有查明实际评委个人偏好。

## 六、对17页初稿的具体修正

保留工程师任务与锅炉案例主线，维持每页一个结论。

1. 第6页流程总览上，以小标记对应赛题要求，避免另加密集功能表；仿真测试集生成和共线性处理有明确位置，细节备份。
2. 第10页展示真实Agent执行，口播说明自然语言如何变成工具计划；第9页展示评价如何反馈前置参数，二者不混为一次普通聊天。
3. 第11页除了绝对RMSE/FIT，需要交代比较对象和测试方式。现有同协议对照若不足，不编造“全量对比提升”或反馈收益；可把公平对照补做列为后续工作。
4. 第14页改为“团队如何把任务交付出来”：三个职责角色、各自可核实贡献、一个关键迭代。现有任务恢复/谱系证据合并到第10或12页。成员与角色对应须向团队核实。
5. 第15页改为“企业开始使用，需要哪些条件与成本”：历史CSV输入、运行环境、LLM接口、计算预算和复核安排。已有本地运行与计划容器部署分开写。成本金额需从真实运行记录/API账单/可核验报价取值，暂不填虚构价格。
6. 第16页呈现试点路径及下一轮验证：目标用户、试点任务、计划验收标准、跨工况边界；不虚构已签约或已上线。
7. 答疑准备独立于17页口播：基线与协议、选段依据、反馈机制、Agent执行约束、失败原因、团队贡献、部署与成本。回答问题占30%，需要专门演练。

建议三句核心记忆：理解工业建模任务；做成真实可复核的闭环；能说清交付、成本和团队贡献。
