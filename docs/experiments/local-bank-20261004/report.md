# 蒸馏跨运行：工作点、动态参数与选模验证

日期：2026-10-04。默认产品算法保持原样。本轮加入两个实验估计模块、修复多运行训练支持证据，完成两轮真实蒸馏数据实验。第一轮新正常运行未通过；第二轮开发回归在 C 上改善，但 B 仍失败，尚不能升级为默认能力。

## 1. 复查发现什么

原始运行元数据表明，压力、进料量和物料组成随运行变化。C 的三个源运行压力约为 1400.93、1391.86、1407.41，底部流量分别约为 0.59、0.47、0.62；新正常运行 op003 的底部流量为 0.13，组成也不同。这些是 YAML 中的物理条件，未将运行 ID 或故障标签用作模型特征。

数据来自 [TUM 连续蒸馏装置公开记录](https://zenodo.org/records/17628963)，涵盖水、正丁醇/水和 OME 三种物料场景。它支持不同运行条件的研究，不能描述成不同工厂验证。

共用一个截距可能把运行水平差异混入动态系数。作为验证假设，新 `operating_points.py` 将每条运行的回归特征和目标分别减去 Train 均值，再估计共享动态参数与独立截距。单元测试能恢复已知的不同截距与相同动态系数，但真实数据效果仍需检验。处理工作点偏移的思路参考 [系统辨识偏移与趋势处理](https://www.mathworks.com/help/ident/ug/handling-offsets-and-trends-in-data.html)，没有使用目标 Test 均值校正预测。

另一个具体缺口是 B 的加热设定值：各源运行内部没有变化，合起来却出现不同水平。合并后的范围不恒定，不等于辨识过该控制量的动态响应。不同压力、组成和工作点可能与它同时变化。现在多运行训练记录分别保存运行内变化、仅运行间变化和各运行范围。

## 2. 第一轮：工作点分离与压力输入

源运行：B op006、op001；C op006、op001、op002。逐运行按时间分 60%/20%/20%，开发只读取前 80%；回归矩阵分别构造，不拼接滞后历史。模型网格为 na=1/2/4、nb=1/2/3、Ridge α=0.01/0.1/1，固定与历史残差两种初始化。

四个方案：共享截距、分离运行截距，以及各自增加 PIC101 压力通道的版本。所有方案比较源时间 Validation 和留一运行 Validation；后者拟合时完全排除被留出的运行。模型、输入、参数及初始化策略均在目标评分前冻结。

目标：

- B op007 正常运行：548 行，505 个评价样本，之前已评分，属于回归。
- C op003 正常运行：120 行，77 个评价样本，此前未评分；它是独立物理运行，但记录很短。
- 均保留从起点到第一个时间异常前的连续 30 秒片段；两条记录没有触发截断。
- T116 和 PIC101 是测量状态通道。评价使用已知输入轨迹，是条件自由仿真，不能宣称部署时提前知道这些未来传感器值。

### 按源 Validation 预先选择的结果

| 目标 | 事先选定方案 | 自由仿真 RMSE | FIT | 持值 RMSE |
|---|---|---:|---:|---:|
| B op007 | 分离运行截距 + 压力 | 2.934665 | -14.024 | 2.728335 |
| C op003 | 原共享截距、原输入 | 2.704298 | -180.391 | 1.576672 |

两者均未超过持值对照。C 上，分离截距及增加压力的候选有更低的目标误差，但没有被源 Validation 选中；不能看到目标成绩后换成这些候选并宣称成功。

第一轮 Source Validation 中，C 的分离截距版本风险为 1.262，原共享版本为 0.971（风险是 RMSE/持值 RMSE 的均值，越小越好）。工作点分离不是普遍修复。

证据：[登记协议](../operating-points-20261004/protocol.json)、[开发结果](../operating-points-20261004/development.json)、[冻结摘要](../operating-points-20261004/freeze-seal.json)、[目标结果](../operating-points-20261004/test-results.json)。开发日志中的两次 JSON 序列化失败保留；修复只转换 NumPy 标量，并在目标评分前记录于 `protocol-repair.json`。既有时间验证多运行基线的追加对照在目标评分前另行登记。

## 3. 第二轮：局部模型与跨运行选模

第一轮结果读出后，C op003 已经成为开发资料。第二轮明确把 B、C 目标都标记为**已观察开发回归**，不再称为独立确认。

新增 `model_bank.py`：每个源运行各自训练、在自己的时间 Validation 选择稳定局部模型。路由规则可根据预测前历史块的仿真误差、训练尺度归一化后的输入工作点距离选择模型，或等权平均各模型的输出。系数不插值、不重估；路由在整个预测区间固定。目标前的观测可以用于路由和初始化，任何目标未来输出都不能用于决定权重。

源留一运行验证用于选择路由规则与输入组。对照全局模型则按源留一运行误差选择结构和压力输入，不再混入“已经训练过该运行”的时间验证成绩。

| 源场景 | 最佳全局模型留一运行风险 | 最佳局部模型留一运行风险 | 预先选择 |
|---|---:|---:|---|
| B | 1.016490 | 1.018276 | 全局、原输入 |
| C | 1.098438 | 1.513016 | 全局、增加压力 |

局部模型没有通过这个比较，没有进入默认产品。所有最佳风险仍超过 1，源跨运行验证总体也没有超过持值对照。

### 开发回归结果

| 目标 | 第一轮事先所选 RMSE | 第二轮源留一运行所选 RMSE | 持值 RMSE | 第二轮 FIT |
|---|---:|---:|---:|---:|
| B op007 | 2.934665 | 2.939352 | 2.728335 | -14.206 |
| C op003 | 2.704298 | **1.334550** | 1.576672 | -38.371 |

C 的开发回归误差下降 **50.65%**，相对持值误差下降 **15.36%**。选中的仍是全局模型，这个改善不能归因于局部模型库。FIT 仍为负，说明误差高于该评价段自身波动；没有获得可靠控制模型的证据。B 未改善。

一个容易误报的结果是 C 的局部等权输出平均，目标 RMSE 为 0.873878，但它的源留一运行风险为 1.621527，未被预先选中。此数值仅作诊断，不作为本轮交付成绩，也不根据它切换方法。

## 4. 误差为什么还大

评分后的诊断没有参与选模，见 [误差分解](error-diagnosis.json)。

- B 的真实输出标准差约 2.574，而所选自由仿真输出标准差约 0.028，预测几乎为常量；偏差只占均方误差约 24.7%。这次主要缺少动态变化的解释，继续移动截距不能消除大部分误差。
- C 第一轮约 79.2% 的均方误差来自整体偏差；第二轮仍约 75.5%。预测均值从 95.180 降到 93.932，实际均值为 92.773，修复了一部分工作点误差。
- C 的在线一步误差约 0.25–0.28，远低于自由仿真的 1.33–2.70。一步评价不断获得实测输出历史，不能把这个分数当成长时预测能力。
- 工作点范围、跨运行动态关系与物料组成是不同层次的信息。范围覆盖不能证明共享动态系数适用。

这些证据支持继续补足真正影响动态的控制输入与运行条件，而不是把更复杂模型或更多窗口自动视作进步。不能由这两条运行推断任何模型都无法拟合。

## 5. 修复、测试与复现

`experiments.py` 的输入支持证据有三项修复：

1. Python 原生布尔值可直接写入 JSON，消除本轮真实实验暴露的序列化错误。
2. 范围包含回归行实际使用的滞后输入历史，排除未使用的尾部。
3. 区分运行内变化和仅运行间变化，保存每条运行的训练参考。

该修复发生在评分后，只调整诊断信息。对冻结的成功全局候选和局部胜出模型共 **226 次**重新拟合对照，系数和截距逐值完全一致，见 [修复核查](post-score-diagnostics-repair.json)。原协议、模型、源结果和目标结果没有覆盖。

本轮新增检查覆盖不同截距的动态系数恢复、仅运行间变化控制量、滞后范围、数据尾部不影响拟合、局部路由不读取未来输入/输出、稳定成员独立仿真和参数不变。完整测试计数与当前代码哈希见 `release-validation.json`。

新增 **14 项测试**。最终完整后端套件 **691 项通过、3 项 Redis 测试跳过**；这 3 项沿用上轮隔离 Redis 的实际通过记录，Worker、正式应用和 Agent 源码未变化，两批取并集共 **694 项不同测试通过**。当前修改文件 Ruff 与 `git diff --check` 通过。前端源码与上轮哈希一致，本轮没有重复前端测试或重新调用云端 Agent。

冻结实验使用的 12 个源文件保存在 `frozen-source/`，每个文件与登记 SHA256 一致。当前诊断修复后 `experiments.py` 的哈希已变化；重新运行原冻结脚本时应在隔离 checkout 中恢复对应源文件，不能跳过哈希检查或覆盖旧结果。

## 6. 产品现状与下一步

正式单数据集 ARX/FIR、全折验收、Agent、报告和导出保持上轮已验证行为。两个新估计模块仍属于实验能力，没有接入默认寻优。未把持值或局部模型的事后最好成绩冒充已验收的辨识结果。

下一步优先收集：同一物料条件下包含实际加热或阀门变化、连续时间轴、压力和流量条件完整的独立正常运行。应在实验前固定训练运行、源验证运行和封存确认运行；新的正常运行作为最终检验，异常压力测试另报。已有 B/C 目标均已观察，后续只能作为开发回归，不能再提供独立泛化证据。
