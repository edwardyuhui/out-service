# 退步原因分析与针对性修改

## 结论

主要问题是训练工况覆盖不足、缺少可辨识的控制输入变化，以及模型估计与初始化对旧稳态的依赖。扩大候选池不能补足缺失的物理信息；短期误差较小也不等于辨识到了可用于控制的动态模型。

本轮完成针对性修改、29,894 次成功模型/验证窗口拟合和多运行覆盖对照。新严格模式在锅炉开发回归上把 RMSE 从 2.079425 降至 1.850525（下降 11.0%）；多运行训练在一条新蒸馏 C 异常运行上从 1.527837 降至 1.091184（下降 28.6%）。后者仍高于持续值基线 0.667378，不能认定模型已达到可靠控制要求。

## 一、原因与证据

### 1. 训练响应变化小，新工况的整体水平未覆盖

蒸馏 B 的训练输出均值约 99.227、标准差约 0.048；Validation 为 98.473 / 0.529，已观察 Test 为 92.819 / 0.934。affine24 冻结模型在 Test 上预测均值约 98.520，仍接近旧水平；约 90.6% 的平方误差来自整体偏差。当前102候选赢家的偏差占约91.8%。

固定原始赢家结构做截距/缩放的 2×2 诊断：B 无截距、无缩放时 RMSE 2.508，最大极点约 0.999984；增加截距、保留原单位时 RMSE 6.134，最大极点约 0.951555。前者很长时间保留起始状态，效果接近持续值基线 RMSE 2.502；后者逐渐返回源训练稳态。原始模型更低的误差部分来自状态记忆，不能据此证明它识别出了正确的输入响应。

这是已观察数据上的事后诊断，不是独立验证。输出标准差小本身不能证明所有输入都缺少激励；下面的控制列检查给出了更具体的可辨识性缺口。

### 2. 常量控制列移除后，跨工况时遗漏了关键变化

| 场景 | 源 Train 加热设定值 | 已观察新运行设定值 | 后果 |
|---|---:|---:|---|
| 蒸馏 B | 固定 135 | 约 125 | 单一源运行无法估计加热变化的影响 |
| 蒸馏 C | 固定 209 | 正常短运行均值约199.709，标准差约3.401 | 删除该列后，模型没有这项变化的输入响应 |

B 源训练的 TV101 也恒为0；本轮新 operating_point_004 异常运行中它发生变化，而纳入的两个正常训练运行仍未提供该通道的变化。即使补入更多恒定运行，仍无法凭空辨识它的动态增益。

将常量列从回归设计中移除可以改善数值问题，但需要保留它的训练工作点和支持范围。该列后来变化时，不能把未辨识出的影响当成零。

“单运行恢复全部控制列”对照与“单运行过滤常量列”几乎相同，说明仅恢复列名并不能增加信息。多运行训练必须真正覆盖不同输入条件，并保留每条运行的独立历史。

### 3. 单步预测、自由仿真和误差补偿回答不同的问题

B affine24 的同一组冻结系数：固定单步 RMSE约0.589，自由仿真约5.990。单步使用先前实测输出，因此能追随当前水平；长时仿真只使用预测状态，会返回模型自身的平衡点。锅炉相应数值约0.213 / 2.623，也有明显差距。

历史扰动补偿也不是普适修复。对同一递推参数的已观察数据诊断中，锅炉 OE 固定初始化 RMSE约1.884；套用方程残差补偿后约7.383。C 的低阶 affine ARX 则从约0.843改善到0.614。补偿必须在各时间窗口中取得证据，不能按模型阶数统一开启。

方程扰动 d 的稳态输出作用为 d/(1+sum(a))。接近单位极点、分母和接近零时，短历史内的噪声或模型误差具有被放大的风险。[OE定义](https://www.mathworks.com/help/ident/ref/oe.html)假设误差加在输出上，不能将其残差直接等同于 ARX 的方程扰动；上述 OE 补偿仅是风险诊断，正式 OE 模块仍使用固定初始化。

### 4. 搜索最优不代表质量通过，原始对照还需检查稳定性

上轮模型层消融选出的原始换热器候选最大极点约1.000010，超过稳定边界。这个短期误差成绩不能作为可用控制模型更优的证据。该消融只原样提取初始估计器和24候选网格，统一外部评分；没有重放最初产品全部质量门禁。正式优化器已有稳定性拒绝，本轮继续保留。

现有优化会报告质量状态，但质量未通过仍可能保存“搜索中的最好模型”。最新 Validation 先筛选少量候选，也可能让只适合最后窗口的模型进入后续比较。

检查中另发现验收函数对空窗口、NaN、Infinity 不够严格，存在误判通过的路径。该漏洞已修复，但本轮分析的历史失败数据为有限数值，因此不能说它造成了所有已观察退步。

两条已观察异常运行还有采样缺口，另一条有重复时间。本轮新的跨运行检验统一采用从开头到首次时间异常的连续30秒片段，避免把缺口当作正常一步；没有插值、串接或按误差挑片段。

## 二、已完成的修改

### 正式接口中的实验模式 validation_guarded

- 保留原102候选前缀。新模式为全部78个固定 ARX 候选增加配对历史补偿，共180候选；旧默认102和旧扰动模式120保持原候选网格。
- 同时比较全量Train与优选Train，允许时间覆盖分层；各候选直接检查全部开发验证窗口。
- 每个窗口都必须有有限证据、正自由仿真FIT，并优于从预测前最后一个已知输出构成的持续值基线，才允许成为新模式赢家。阈值是内部实验规则，不是赛题官方指标，也不是部署证书。
- 未通过时保留候选失败原因和折内指标，返回没有通过验证的模型；不将相对最好自动包装为可靠结果。
- 修复空/非有限验收证据。
- 当提供真实时间轴时，仅检查 Train 的间隔：重复、倒序或相对中位间隔超过5%的缺口会阻止该模式；不自动重采样。没有时间轴时明确记录 unavailable。API输入文件中的名义时间轴不证明原始测量时间没有缺口。
- 前端已增加“实验：全折验证与质量验收”选项。默认仍为 established。

### 独立多运行估计模块与输入支持检查

- experiments.py 分别构造每条运行的动态回归，再估计共享参数；没有跨运行的输出滞后项，也没有人工阶跃。
- 每条运行使用自己的 Train 前缀，缩放、权重、支持范围均只从 Train 获取。默认使各运行总权重相同，防止长稳态运行压过短动态运行。
- 保留运行名、原始索引、训练区间、权重和输入范围；support.py 区分恒定输入后来变化、输入范围外推、元数据缺失等状态。
- 多运行估计仍是独立实验模块，未接入正式单数据集模型家族，不自动替换默认 ARX/FIR。不同运行的相关性并不自动证明物理因果。

## 三、真实数据实验

### 当前默认与严格模式

5组既有真实过程数据，每模式5个预先指定种子，每种子1 Trial；每模式各25次搜索。严格模式对所有候选检查全部验证窗口，计算成本明显更高。两模式的覆盖采样和时滞提案可能不同，这是一组完整搜索方案对照，不能将全部收益只归因于某一个门禁。

| 数据 | 默认 Val所选模型 Test RMSE | 严格模式结果 |
|---|---:|---|
| boiler | 2.079425 | 1.850525 |
| exchanger | 0.791812 | 5个种子均无候选通过全部验证窗口 |
| distillation_a | 1.880472 | 5个种子均无候选通过全部验证窗口 |
| distillation_b | 3.395185 | 5个种子均无候选通过全部验证窗口 |
| distillation_c | 0.756885 | 5个种子均无候选通过全部验证窗口 |

锅炉所有5个种子都找到通过开发验证的候选。其它4组在本次预算内未通过；这表示未获得满足本实验验收规则的证据，不能据此断言任何算法都无法建模。严格模式没有伪造一个缺失模型的Test误差，也没有将持续值预测冒充辨识模型。

源数据此前已评估，属于开发回归。另预先选择3条未评估的op005异常运行用于压力检查，源模型选择在评分之前冻结；它们来自同一装置，不能称为3个新工厂。默认模式A/B的误差分别约3.971/0.229，高于相应持续值基线3.955/0.204；C约1.617低于持续值2.601，但FIT仍为负。严格模式因没有源验证通过模型，保留“不评分”状态。

### 操作条件覆盖的独立消融

B使用正常运行op006、op001；C使用op006、op001、op002。它们此前已检查，作为开发资料。各运行分别60/20/20切分；模型阶数1/2/4、输入阶数1/2/3、固定时滞1，共同历史保护10，正则化与初始化只在各源Validation选择。各方法都在相同源运行Validation上比较；单运行基线不会用额外运行的Train，验证结果可参与选模。

与前一组产品实验的时滞、保护区间、模型池不同，不能把两组RMSE直接混为同一对照。各方法的训练数据量也不同。目标预测统一从第43点开始，并且所有未来输出替换为NaN时预测逐值不变。

| 新目标记录 | 单运行过滤常量列 | 单运行全部控制列 | 多运行全部控制列 | 事先Val选择 | 持续值基线 |
|---|---:|---:|---:|---|---:|
| distillation_b op004异常 | 0.246331 | 0.246331 | 5.413205 | single_filtered | 0.256011 |
| distillation_c op004异常 | 1.527837 | 1.527837 | 1.091184 | multiple_full_controls | 0.667378 |

C的多运行模型由源Validation预先选择，目标RMSE下降约28.6%。输入支持检查仍提示部分输入范围外推；其误差高于持续值，仍未达到可靠泛化。B的多运行方案在源Validation较差，预先选择单运行；新目标也确实退步，但不能用看到的目标成绩倒回去挑方案。

B的各训练方案均未覆盖TV101的变化，新的输入支持检查将这条目标标记为unsupported；其误差数值仅作为研究诊断，不推荐该工况模型。C多运行支持检查不再出现恒定加热控制变化的缺口，但仍有范围外推风险。

这组实验支持“补足运行覆盖比恢复列名更有效”的C案例，同时明确保留B反例。它不支持“增加数据必然改善”或“已经解决跨厂泛化”的结论。

## 后续应收集和验证什么

优先寻找相同物料场景下含真实加热/阀门阶跃的连续运行，使待辨识控制变量有变化；保留控制变量角色、未激励的工作点及原始时间轴。增加运行时先检查物料与动力学是否相同，再用完全保留的新正常运行检验，不能用异常压力测试替代正常工况验证。

只有这些证据补足后，才值得增加局部工作点模型或更复杂的OE结构。目前全局共享线性模型、未测扰动、短验证窗口与输入范围外推仍是限制。
