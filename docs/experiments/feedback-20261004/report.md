# A14 算法与完整流程验证（2026-10-04）

本轮完成了训练工况证据、全折验收剪枝、验证反馈预算保护，以及真实 DeepSeek Agent 全流程的修复。新卷绕数据上，全折验收方案的两个输出误差均低于当前默认方案；最初的即时反馈方案反而更差，失败结果保留。蒸馏跨运行问题仍未解决。

## 1. 原因与修改

### 模型不知道自己在哪些工况下得到过训练

过去的训练范围容易使用整段 Train，包含没有参加拟合的行；删掉控制量后也会丢失其工况变化证据。这样可能将外推描述成已覆盖工况。

现在保存正权重有效回归行及其实际输入滞后历史的范围。删掉的控制量通过逐行对齐的变量优选版本血缘保留为监测信息，不进入模型特征。范围、来源版本和恒定状态随模型冻结，Test 回放不会重新计算训练参考或更新系数。没有证据时明确显示不可用。训练中恒定却在 Validation 中变化的控制量，会使全折验收候选失败；一般范围外推保留警示。

范围覆盖不是动态关系不变的证明。不存在有效激励时，系统建议补充真实运行数据，不能通过生成测量或调参补出缺失响应。

### 失败候选仍重复计算后续验证折

全折验收先检查最新验证折；不满足自由仿真 FIT、持值对照或欠激励规则的候选，停止后续计算。所有通过的候选仍按完整折分数比较。穷举对照测试验证了剪枝与完整计算选择同一胜出模型。

已见锅炉数据的固定种子回归中，成功结构拟合由 **1080 次降至 704 次，减少 34.8%**，模型参数、训练行、权重和 Test RMSE **1.8505245577** 完全一致。这是拟合次数减少，没有据此声称运行时间同比下降或精度提高。见 [剪枝回归](pruning-regression.json)。

### 即时反馈占用了探索机会

初版每次试验后立刻排入反馈参数。在总预算只有两次时，第二次被第一组参数的局部变体占据，延迟等参数缺少独立探索。卷绕两个输出上，源 Validation 的最佳分数和 Test 都比关闭反馈更差。

修复后的全折验收反馈使用 `reserved_feedback_budget_v1`：

- 总预算小于 4 次，不排入反馈试验。
- 先执行 3 次搜索，再允许一次反馈；之后按每 4 次最多一次安排。
- 反馈最多占总预算的四分之一，排队状态和实际参数保留；未改善时保留最佳模型。
- 动作可调整片段数、窗口长度、时间覆盖和候选窗口方案，依据仅来自 Validation。

规则由搜索预算被挤占及源 Validation 失败共同支持，没有根据 Test 调目标权重。默认 `established` 策略的反馈行为保持原版本；新预算保护用于 `validation_guarded`。少预算等价性测试和真实卷绕 API 重放确认了当前两次试验的结果等于冻结的关闭反馈方案。这个重放属于回归证据。

### Agent 报告丢失中间阶段证据

真实全流程暴露出：报告原来跳过执行任务的大模型撰写，且按最终版本过滤了明确关联的中间版本记录，造成选段、时滞等图缺失。

现在报告只引用当前执行明确关联的步骤、处理记录和 Study；中间版本证据保留。大模型引用区分 `step` 和 `run`，未知来源或错误类型会被拒绝。报告分别展示初始模型 Validation、优化模型 Validation 和冻结最终模型 Test。寻优图使用实际试验的累计最佳值，失败或非有限得分不能改善曲线。清洗图按同一输出通道和共同唯一时间戳对齐，重复时间戳组不按顺序猜测配对。

## 2. 新真实数据与冻结协议

使用 KU Leuven DaISy 的真实卷绕试验装置记录：塑料带卷绕系统，2500 行、采样间隔 0.1 秒，三个测量角速度、两个电机电流设定值和两个张力输出。两个输出来自**同一次物理运行**。

来源：[官方数据说明](https://ftp.esat.kuleuven.be/pub/SISTA/data/process_industry/winding.txt)、[原始数据](https://ftp.esat.kuleuven.be/pub/SISTA/data/process_industry/winding.dat.gz)。原始文件和转换摘要保存于公开数据目录。说明没有给出实际采集日期、全部工程单位或单独许可证声明；CSV 日期是人工时间原点，不能描述成真实采集日。测量速度作为已知条件输入，不代表部署时可以预先获得。

协议在评分前登记，全部模型冻结后才读取 Test 分数：

- 时间顺序 Train/Validation/Test = 60%/20%/20%，公共历史保护长度 43。
- 固定种子 42、7、19、31、20261004；每个方案每个种子两次试验。
- 种子胜出者仅由源滚动 Validation 分数选择，平分时按固定顺序。
- 开发阶段屏蔽所有 Test 尾部数据；评价检查未来输出替换为 NaN 不改变预测。
- 当前默认网格 102 个候选，全折验收网格 180 个候选，比较全量和优选训练。
- 试验次数相同，模型拟合预算不同。两个 guarded 方案的网格、折和验收规则相同，仅初版反馈开关不同。

证据：[协议](protocol.json)、[开发结果](development.json)、[冻结摘要](freeze-seal.json)、[Test 结果](test-results.json)。它们保留评分前代码哈希；之后预算保护及报告修复不覆盖这些文件。当前代码及验证摘要另存于 `release-validation.json`。

## 3. 时间留出结果

每个输出 Test 457 个样本。以下是由 Validation 选定的种子模型，**没有按 Test 挑种子**。

| 输出 | 方案 | Test 自由仿真 RMSE | Test FIT | 选定种子 |
|---|---|---:|---:|---:|
| tension_1 | 当前默认 established | 0.400044 | 60.604 | 20261004 |
| tension_1 | 全折验收，关闭初版反馈 | **0.303074** | **70.153** | 7 |
| tension_1 | 全折验收，初版即时反馈 | 0.426079 | 58.040 | 42 |
| tension_3 | 当前默认 established | 0.543395 | 42.541 | 20261004 |
| tension_3 | 全折验收，关闭初版反馈 | **0.484620** | **48.756** | 42 |
| tension_3 | 全折验收，初版即时反馈 | 0.664844 | 29.699 | 20261004 |

全折验收关闭初版反馈相对当前默认，RMSE 分别下降 **24.24%** 和 **10.82%**。持值预测 RMSE 分别为 1.155057 和 1.173441。全部选定模型的 Test 都存在输入范围外推，报告保留提示。

源 Validation 最佳分数也解释了反馈失败：

| 输出 | 当前默认 | 全折验收关闭反馈 | 初版即时反馈 |
|---|---:|---:|---:|
| tension_1 | 0.177367 | 0.184193 | 0.123391 |
| tension_3 | 0.035688 | 0.010217 | -0.051024 |

因此，不能把提升归因于反馈本身。两个输出是一次运行的时间留出，没有证明化工跨运行迁移；两次试验也不代表充分搜索或收敛。当前更大预算的反馈已验证能实际执行，还未证明普遍提高精度。

本表基线是当前默认 102 候选方案。最初算法是 Git `f832237` 的 24 候选原始 OLS/Ridge 版本，本轮没有重新与最初算法做独立冻结对比；历史对照见 `initial-and-oe-20261003`。

## 6. 当前结论与下一项重点

可以确认：工况证据可追溯，低预算反馈不再挤掉搜索，失败候选计算减少，真实云端 Agent 与图文报告、最终数据交付闭环跑通；新卷绕时间留出有明确改善。

仍需解决：蒸馏跨运行效果不稳定、未激励控制量的响应缺少依据，以及更大试验预算下反馈效果能否稳定提升。下一项实验应收集具有相关控制量变化的独立真实运行，预先固定训练运行、Validation 运行与封存 Test 运行；使用一致输入与历史条件比较模型结构和数据选择。OE 与多运行模型目前仍是离线实验，不能描述为已交付的正式产品能力。
