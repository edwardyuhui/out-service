# 多步 OE 实现与泛化验证

新算法已接入建模 API、模型保存与回放、前端模型选择。独立双水箱测试优于最初线性算法，但蒸馏跨工况回归仍失败。**目前不能宣称已经完成普遍泛化，也不将 OE 设为默认优化策略。**

## 实际修改

新增 `algorithms/identifiability/multihorizon.py`，估计稳定的共享分母 MISO OE 模型。最终系数沿用项目已有线性差分方程，兼容现有冻结模拟器。

- 训练目标同时包含 1、16、64 步及整个连续区间的模拟误差。各时域权重相同；每个训练区间总权重相同。
- 每个训练块只在起点读取此前的观测历史，块内递推使用模型输出。长期模拟误差直接参与参数估计。
- 用 Schur 反射系数约束分母稳定；两组初值搜索，预算内未收敛明确报错。
- 标准化、初值、目标和历史均限制在指定 Train 区间及其必要历史中。不同运行、断开的选中片段分别模拟，不拼接边界。
- API 新增 `model_type="OE"`，页面入口为“多步模拟 OE（实验）”。保存模拟时域、求解预算、训练区间与实际输入支持范围；保存模型评价不重新拟合。

当前支持分母阶数 1–4、固定预测初始化、截距与标准化。`estimator="ridge"` 在 OE 下表示 Ridge 初始化，随后使用受约束的模拟误差优化；前端据此显示实际求解方式。每个连续片段至少 16 行，且行数多于参数数。只接受 0/1 可靠性权重，软权重显式拒绝。默认 Optuna/Agent 自动选模仍使用既有 ARX/FIR 策略；OE 尚未加入自动搜索网格。

## 首次独立测试：真实双水箱

来源：[Cascaded Tanks 官方数据说明](https://www.nonlinearbenchmark.org/benchmarks/cascaded-tanks)，划分参考[官方加载器](https://github.com/MaartenSchoukens/nonlinear_benchmarks)。这是泵驱动的真实串联双水箱装置，包含溢流非线性；输入为泵控制，输出为液位传感器信号。它是 SISO 流程实验，不能充当多输入或跨工厂证明。

官方估计记录和测试记录各 1024 点。开发阶段只加载 `uEst/yEst`；测试 `uVal/yVal` 在所有候选及赢家封存后加载。训练使用估计记录 `[50,614)`，两个源 Validation 区间为 `[665,1024)`、`[839,1024)`，它们重叠，不是两次独立实验。按两区间 RMSE/持值基线的均值选模，未在选模后重训。测试只使用前 50 点初始化，再连续模拟 974 点。

| 方法 | 测试 RMSE（V） | 测试 FIT |
|---|---:|---:|
| 最初 Git `f832237` 的原始估计器、24 项网格 | 1.150521 | 45.73% |
| 当前标准化估计器、相同 24 项网格 | 0.760466 | 64.13% |
| 单段 OE 模拟训练、24 项网格 | 0.716500 | 66.20% |
| 新多步 OE、24 项网格 | 0.719311 | 66.07% |

源 Validation 选择的是多步 OE，结构 `na=3, nb=1, nk=1, alpha=0`。相比最初估计器，其测试 RMSE 下降 **37.48%**；相比标准化 24 项对照下降 **5.41%**。单段 OE 的测试误差略低约 0.39%，因此没有证据认为多步目标本身更优。

这是同训练区间、同候选数量的**模型部分对照**：没有重放最初的整个预处理/寻优流程，也没有比较当前默认 102 项完整网格。数值求解预算并不相等。不能把表中的改善全部归因于多步训练。

四个冻结模型都通过将预测起点后的真实输出替换为 NaN 的不变性检查。测试过程没有重新估计系数；已保留协议、全部候选、封存哈希、结果和原始代码快照。

## 已知蒸馏运行：迁移仍然失败

另外在原来的真实连续蒸馏数据上完成多输入跨运行回归。B 使用源运行 006/001，目标为 007；C 使用源运行 006/001/002，目标为 003。两个目标此前都看过，**仅作为开发回归**。每个候选必须在留一源运行验证中排除被留出运行的训练数据和标准化统计。

本轮使用每组 8 项网格，比较 pooled ARX 与多步 OE，各有基础输入和附加压力两种版本。固定预测初始化，不添加目标工况偏置；这与之前带历史残差补偿的实验不同，不能直接比较成版本收益。T116/PIC101 为已知的传感器条件轨迹，不能当成未来未知条件下的开环预测证据。

| 目标 | 源 Validation 选中的方法 | 源验证误差/持值 | 目标 RMSE | 目标持值 RMSE |
|---|---|---:|---:|---:|
| B007，505 点 | 多步 OE，基础输入 | 0.861 | 7.837 | 2.728 |
| C003，77 点 | 多步 OE，附加压力 | 7.146 | 3.692 | 1.577 |

两者均失败。B 的源验证均值通过了持值基线，但目标仍明显失效；C 在源验证阶段就应被拒绝用于部署。C 某个未被源验证选中的 pooled 模型在目标上更好，也没有据此换赢家。

冻结预测的事后分解显示：B 的平均偏差平方占 MSE 的 **89.3%**，C 为 **80.4%**。B 目标均值为 91.785，预测均值 99.191；C 分别为 92.773 和 96.083。主要误差仍表现为运行间基线偏离。这个分解不能单独证明物理原因；它说明稳定性和多步训练未能自动识别不同工况的平衡点，继续增加阶数不足以解决问题。

详细证据在 `../multihorizon-transfer-20261004/`。下一步应先补齐可用的工况变量、各工况内的输入变化和更长的独立运行，再决定是否加入受约束的非线性模型或预测前基线校准。已经查看过的目标不能再次称作独立确认数据。
